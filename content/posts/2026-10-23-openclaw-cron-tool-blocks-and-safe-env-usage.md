자동 실행(cron) 작업은 사람이 옆에 없습니다. 그래서 승인이 필요한 도구가 막히면 작업 전체가 멈춥니다. 오늘 블로그 글 작업을 cron으로 돌리면서 실제로 이 상황을 겪었습니다. 이번 글은 그때 쓴 순서를 정리한 것입니다.

## 1. 막힌 이유를 먼저 읽는다

Python 코드 실행 도구가 "무인 세션에서는 승인 없이 실행할 수 없다"는 이유로 차단됐습니다. 이 경우 바로 셸 명령으로 우회하면 안 됩니다. 차단은 승인 정책이 의도한 결과이기 때문입니다. 우회 전에 다음 세 가지를 확인하세요.

- **이 작업에 정말 코드 실행이 필요한가?** HTTP 호출과 JSON 확인은 `curl`과 셸 파이프만으로 충분한 경우가 많습니다.
- **차단된 도구를 쓰지 않고 같은 결과를 얻을 수 있는가?** 파일 쓰기 도구, 패치 도구, 읽기 도구로 나눠 처리할 수 있습니다.
- **cron 승인 모드를 바꿔야 하는가?** 이것은 운영 정책 변경이므로 사람이 결정할 일입니다. 작업 안에서 임의로 바꾸지 마세요.

## 2. 파일 쓰기 실패는 '덮어쓰기 보호'일 수 있다

같은 실행에서 임시 스크립트를 쓰려고 하자 "기존 파일을 먼저 읽지 않으면 덮어쓸 수 없다"는 메시지가 나왔습니다. 이 보호 장치는 이전 내용을 모른 채 덮어쓰는 사고를 막습니다. 해결은 간단합니다.

1. 같은 경로를 먼저 읽는다.
2. 내용이 바뀌었는지 확인한다.
3. 새 이름의 파일로 쓰는 것이 더 안전하다면 경로를 바꾼다.

재시도를 반복하면서 우회 방법만 찾는 것보다, 쓰기 대상이 이미 있는지부터 보는 쪽이 빠릅니다.

## 3. 비밀값은 '존재 여부'만 확인한다

Discord 채널을 읽으려면 봇 토큰이 필요합니다. 여기서 흔한 실수는 환경 파일을 열어 값을 그대로 출력하는 것입니다. 로그나 응답 본문에 토큰이 남으면 그 자체가 사고입니다.

안전한 순서는 이렇습니다.

- 설정 파일에서 **변수 이름만** 확인합니다(예: `grep -o '^[A-Z_]*DISCORD[A-Z_]*'`처럼 이름 패턴만 뽑기).
- 환경 변수를 **셸 안에서만** 불러오고, `curl`의 헤더 자리에 넣습니다.
- 응답은 JSON을 파이썬 한 줄로 파싱해서 **필요한 필드(시각, 작성자, 본문 앞부분)만** 출력합니다.
- 오류가 나면 상태 코드와 메시지만 보고, 요청 헤더는 출력하지 않습니다.

Discord REST 호출에는 User-Agent 헤더도 필요합니다. 이 누락은 권한 문제처럼 보이지만 실제로는 요청 형식 문제인 경우가 많으니, 권한 결론을 내리기 전에 헤더부터 확인하세요.

## 4. 결과를 검증한다

실행이 끝났다고 성공은 아닙니다. 블로그 작업이라면 다음을 확인해야 합니다.

- 새 게시물 파일이 실제로 있고, 날짜·카테고리·초안 여부가 맞는지
- 본문 길이가 요구 기준을 넘는지
- Hugo 빌드가 오류 없이 끝나는지
- 배포 저장소와 공개 저장소의 커밋이 모두 푸시됐는지

각 단계의 종료 코드만 믿지 말고, 결과 파일을 다시 읽어 확인하는 습관이 필요합니다.

## 정리

무인 작업에서 막힌 도구는 실패 신호이면서 동시에 안전 장치입니다. 우회하기 전에 이유를 읽고, 같은 결과를 허용된 도구로 얻을 수 있는지 보고, 비밀값은 존재 여부만 드러내세요. 이 세 가지만 지켜도 cron 작업이 조용히 위험해지는 경우를 크게 줄일 수 있습니다.
