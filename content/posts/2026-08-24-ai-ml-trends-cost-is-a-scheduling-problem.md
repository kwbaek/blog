AI 비용을 말할 때 대부분의 조직은 먼저 모델별 입력·출력 토큰 단가표를 펼칩니다. 하지만 오늘 공개된 신호들을 함께 보면, 비용의 승부처는 단가표보다 **언제 어떤 경로로 어떤 크기의 모델을 호출하느냐**에 가까워지고 있습니다. 같은 모델이라도 시간대, 캐시 적중 여부, 컨텍스트 길이, 실행 환경에 따라 실제 비용 구조가 달라지기 때문입니다.

## 가격표에 이미 스케줄이 들어왔다

[DeepSeek 공식 가격표](https://api-docs.deepseek.com/quick_start/pricing)는 V4 Flash와 V4 Pro에 대해 peak와 off-peak 가격을 나눠 공개하고 있습니다. 평일 UTC 01~04시와 06~10시가 peak이고 그 밖의 시간이 off-peak입니다. 예를 들어 V4 Pro의 입력 캐시 적중 가격은 100만 토큰당 off-peak 0.022달러, peak 0.044달러이며, 출력도 1.98달러와 3.96달러로 두 배 차이가 납니다. 캐시 적중과 미적중의 차이까지 합치면, 같은 업무를 같은 모델로 실행해도 호출 시점과 입력 재사용 여부가 청구액을 바꿉니다.

이것은 단순 할인 이벤트가 아닙니다. API 사업자가 가격표에 시간대를 넣었다는 것은 추론 수요가 전력망처럼 시간에 따라 밀집된다는 뜻입니다. 기업이 비동기 리포트, 임베딩, 대량 분류, 평가셋 재실행을 피크 시간에 몰아 넣는다면 모델을 바꾸지 않고도 비용을 키우게 됩니다. 반대로 즉시성이 필요한 고객 응답만 peak에 남기고 나머지를 off-peak 큐로 보내면 품질을 유지한 채 비용을 줄일 수 있습니다.

## 단가가 낮아져도 운영비는 내려가지 않는다

[AWS의 멀티 에브리thing 아키텍처 글](https://aws.amazon.com/blogs/machine-learning/scaling-agentic-ai-enterprise-patterns-without-vendor-lock-in/)은 프레임워크·모델·프로바이더가 섞이는 환경에서 제어 평면과 실행 평면을 분리하고, 관측성·거버넌스·동적 라우팅을 통합하라고 제안합니다. 핵심은 특정 모델을 고르는 일이 아니라 요청마다 적합한 실행 경로를 선택할 수 있는 운영 계층입니다.

여기에 [Llama-Mobile 연구](https://arxiv.org/abs/2608.21134)의 결과도 연결됩니다. 연구진은 학습 셋업에 접근하지 않고 모델 자체가 만든 데이터로 VLM을 2.7비트로 양자화해, Llama 3.2 11B Vision 모델을 3.7GB까지 줄였습니다. 이 결과가 곧 모든 모바일 업무의 상용화를 의미하지는 않지만, 추론 비용의 분모가 클라우드 토큰만은 아니라는 점은 분명합니다. 네트워크 왕복, GPU 대기열, 개인정보 전송, 엣지 장치의 메모리 비용까지 포함하면 작은 모델을 가까운 곳에서 실행하는 경로가 더 싸고 안전할 수 있습니다.

## 실무에서는 ‘비용 라우터’를 먼저 만든다

따라서 모델 목록만 관리하는 방식은 부족합니다. 요청을 세 가지 축으로 분류해야 합니다.

1. **긴급도**: 사용자가 기다리는 실시간 요청인가, 몇 시간 늦어도 되는 배치인가.
2. **난이도**: 단순 분류·요약인가, 장기 추론과 도구 호출이 필요한 업무인가.
3. **데이터 민감도**: 외부 API로 보내도 되는가, 사내 또는 엣지 경로가 필요한가.

그 다음 실시간·고난도·민감 데이터 요청은 승인된 고성능 경로로 보내고, 반복 배치·낮은 긴급도·캐시 가능한 요청은 off-peak와 소형 모델, 로컬 양자화 경로로 보냅니다. 이때 평균 토큰 단가만 보지 말고 요청당 지연시간, 재시도율, 캐시 적중률, 실패 후 사람 개입 비용까지 함께 기록해야 합니다.

AI 비용 최적화의 다음 단계는 “더 싼 모델을 찾기”가 아닙니다. **업무의 시간·난이도·민감도에 맞춰 호출 시점과 실행 위치를 설계하는 것**입니다. 모델 가격표를 읽었다면, 다음으로 읽어야 할 것은 자신의 큐와 라우팅 로그입니다.
